## 0. 一页摘要

HOCHO 是一个基于 MOSS Live 的 Chrome Manifest V3 视频陪看助手。

核心结构是**一条主会话 + 一条视频监听会话**：

| 角色 | 连接 | 输入 | 职责 | 是否发声 |
|---|---|---|---|---|
| 主会话 | MOSS Live 连接 #1 | 用户麦克风、当前画面（标签页/窗口/屏幕/摄像头） | 听用户、回答、角色表达、主动评论 | 是 |
| 视频监听 | MOSS Live 连接 #2 | 标签页或窗口/屏幕的视频声音 | 只输出视频事实、台词、人物、剧情节点、梗、音乐变化、按类型摘要 | 否 |

视频监听把内容通过 `session.thinking.append` 静默注入主会话；主会话根据这些上下文，由角色决定是否主动评论、评论什么。

**为什么不用一条连接混音：** MOSS Live 文档明确「一条连接只接一个说话人」。视频声和麦克风混成一路会让服务端把视频台词误判成用户说话，触发错误 VAD、打断和回复。

**为什么需要本地 Relay：** 浏览器原生 WebSocket 无法设置 `Authorization` 请求头，而 MOSS Live 握手必须带 Bearer Key。Key 只存在于项目根目录 `.env`，由本地 Relay 读取；插件、前端页面、日志、仓库都不保存 Key。

## 1. 决策清单（已确认）

### 1.1 权限

| 项目 | 决策 |
|---|---|
| 覆盖范围 | 默认当前网页覆盖（`activeTab`）；设置里可手动开启「所有网站自动跟随」（`<all_urls>`），关闭即撤销 |
| 申请时机 | 按需申请：麦克风首次开始陪看时；摄像头仅打开摄像头开关时；`<all_urls>` 仅在主动开启全覆盖时 |
| 授权入口 | 独立悬浮窗直接请求麦克风/摄像头；Side Panel 遇到权限弹窗问题时打开完整扩展授权页，授权完成后自动关闭并通知原陪看界面继续 |
| 窗口/屏幕 | 使用 Chrome 原生 `desktopCapture.chooseDesktopMedia` 选择器，不依赖 `<all_urls>` |
| 取消共享 | 提示「屏幕共享被取消」，不开始窗口/屏幕陪看 |

### 1.2 采集

| 项目 | 决策 |
|---|---|
| 默认来源 | 当前标签页 |
| 可选来源 | 窗口/屏幕模式；摄像头独立开关，默认关闭 |
| 画面参数 | 默认 1 帧/秒，长边 768，JPEG 质量 0.75 |
| 窗口/屏幕音频 | 画面优先，音频可选；有共享音频就监听，没有则显示「窗口/屏幕音频不可用」，不影响开始 |
| 标签页视频轨 | `tabCapture` 同时取音频和视频轨；画面优先从视频轨取帧，视频轨不可用时回退截图 |
| 关闭窗口 | 关闭独立悬浮窗 / Side Panel 不结束会话；会话继续在 offscreen 运行，重新打开恢复状态和历史 |

### 1.3 视频声音

| 项目 | 决策 |
|---|---|
| 是否混入麦克风 | **不混音**；视频声音走独立的第二条 MOSS Live 连接 |
| 默认开关 | 「分享视频声音」默认开启，处于待命状态 |
| 建连阈值 | 检测到约 300ms 视频声音后建立第二条连接 |
| 断连阈值 | 连续 30 秒静音后断开第二条连接；开关保持开启，下次有声自动重建 |
| 断开后上下文 | 本地保留视频类型、滚动摘要和最近关键台词，重连时补回 |
| 视频声音呈现 | 视频监听内容静默注入主会话，不显示成用户消息、不播放监听连接的 TTS |
| 视频原声回放 | 本地回放给用户（`tabCapture` 接管后原标签页会静音）；主 Agent 或主动评论发声时压低到约 16%，平滑恢复 |
| 视频监听身份 | 使用当前角色人设，但提示词明确限定「只输出视频事实和摘要，不对用户说话、不扮演评论者」 |

### 1.4 视频类型与摘要

| 项目 | 决策 |
|---|---|
| 类型集合 | 科普/知识、短视频/段子、连续剧/电影、音乐/MV、直播/体育、通用 |
| 判断方式 | 自动判断 + 用户可手动修正；界面显示当前类型 |
| 摘要层级 | 按类型不同，详见 §4.3 |
| 注入频率 | 视频监听有输出时逐条静默注入；同时按类型维护滚动摘要（连续剧/科普约 30–60 秒更新，短视频按段更新） |
| 持久化 | 按页面 URL / 视频标识保存滚动摘要和关键台词；再次打开同一个视频时恢复 |
| 切换目标 | 切换陪看目标时清空旧视频的摘要和关键台词；主会话和聊天历史保留 |

### 1.5 主动评论

| 项目 | 决策 |
|---|---|
| 归属 | 角色能力，由**主会话**发声；视频监听只提供上下文 |
| 频率 | 三档：安静 / 正常 / 活泼；在角色编辑器里直接选默认档 |
| 优先级 | 用户说话 > 主 Agent 回答 > 主动评论 |
| 视频原声 | 任何一方说话时视频原声都压低到约 16% |
| 触发方式 | 主会话通过 `session.commentary.append`（MOSS Live 文档的「可向用户表达的进度或结果」通道）请求主连接主动播报 |
| 风险 | 该通道原本用于后台委派，是否能稳定触发主连接主动播报，**必须用真实 MOSS Key 冒烟验证**；不通过时先回来讨论，不擅自换实现 |

### 1.6 消息与会话

| 项目 | 决策 |
|---|---|
| 用户消息 | 只有最后一次麦克风活动后 **2 秒内**的 final 转写，才显示为「我」说的话 |
| 视频监听消息 | 永远不显示成用户消息；默认不显示任何旁听记录 |
| Agent 消息 | 按 `run_id` 建一条消息；流式更新同一条；历史只追加不覆盖 |
| 消息 ID | 用户消息 `user-<turnKey>`；Agent 消息 `assistant-<run_id>` |
| 历史持久化 | 写入 `chrome.storage.local`，跨关闭窗口、切换标签页、浏览器重启保留 |
| 切换陪看目标 | 点击插件图标切换采集目标；保留 MOSS Live 会话、`session_id`、对话历史 |
| `session_id` | 持久化保存；启动/重连时优先 resume，过期则清掉并新建一次 |
| 重连 | 首次连接失败和已建会话后的非主动断线，都最多自动重试 3 次，指数退避 1s/2s/4s |
| 错误详情 | 状态栏持续显示状态；错误详情可展开，包含 WebSocket 关闭码、MOSS 关闭原因、Relay 错误 |

### 1.7 界面与角色

| 项目 | 决策 |
|---|---|
| 主界面 | **独立悬浮窗为主**；Side Panel 作为可选入口 |
| 悬浮窗实现 | 独立 Chrome 窗口，不绑定任何网页 DOM |
| 始终置顶 | 支持时使用 Document Picture-in-Picture；不支持时按钮给出提示 |
| 角色系统 | 保留角色、人设、音色，收进高级设置；默认角色「绫」 |
| 旧弹窗 | 保留为 legacy，不作为默认入口 |

### 1.8 Key / Relay

| 项目 | 决策 |
|---|---|
| Key 存放 | 项目根目录 `.env`，`.gitignore` 忽略；提供 `.env.example` |
| 启动方式 | 用户手动运行 `npm run relay`；插件只连本地 Relay |
| Relay 地址 | 默认 `ws://127.0.0.1:8787`，只监听本机回环 |
| Key 暴露 | 插件、前端、日志、仓库都不出现 Key；Relay 日志只打印「已配置/未配置」 |
| 远程部署 | 第一版不做远程 Relay 服务器 |

## 3. 权限模型

### 3.1 权限清单

| 权限 | 用途 | 默认状态 | 何时申请 |
|---|---|---|---|
| `activeTab` | 当前标签页临时授权 | 安装时 | 点击插件图标时 |
| `tabCapture` | 标签页音频/视频轨 | 安装时 | 使用当前标签页模式时 |
| `desktopCapture` | 窗口/屏幕共享 | 安装时 | 使用窗口/屏幕模式时 |
| `<all_urls>`（可选） | 所有网站自动跟随、截图 | **关闭** | 设置里主动开启「所有网站自动跟随」时 |
| 麦克风 | 用户语音 | 未授权 | 首次开始陪看时 |
| 摄像头 | 可选画面 | 未授权 | 打开摄像头开关时 |
| `offscreen` | 会话宿主 | 安装时 | — |
| `storage` | 设置和历史 | 安装时 | — |
| `sidePanel` | 可选 Side Panel | 安装时 | — |

### 3.2 权限流程

**独立悬浮窗（默认路径）**

1. 用户点击「开始陪看」。
2. 悬浮窗内直接 `getUserMedia({ audio: true })` 请求麦克风。
3. 如果用户打开摄像头开关，再请求 `getUserMedia({ video: true })`。
4. 请求结果写入状态栏和麦克风/摄像头指示器。

**Side Panel（兜底路径）**

1. Side Panel 内点击「开始陪看」。
2. 如果 `navigator.permissions.query` 显示麦克风/摄像头未授权，打开完整扩展页 `src/permission/permission.html?need=microphone,camera`。
3. 授权页只显示本次需要的项；用户逐项点「允许」。
4. 全部允许后显示完成面板，用户点「完成，回到网页」，页面自动关闭。
5. 授权页通过 `chrome.runtime.sendMessage` 通知原陪看界面继续连接。
6. 授权页不会在全部允许后自动关闭，避免用户看不清剩余项。

**所有网站自动跟随（可选）**

1. 设置页开关「允许所有网站自动跟随」。
2. 打开时调用 `chrome.permissions.request({ origins: ['<all_urls>'] })`。
3. 授权成功后，切换标签页时自动跟随，不需要每次点图标。
4. 关闭开关时调用 `chrome.permissions.remove` 撤销。

## 4. 采集与视频监听

### 4.1 主画面采集

- **标签页模式（默认）**：`chrome.tabCapture.getMediaStreamId({ targetTabId })` → offscreen `getUserMedia({ audio: tab, video: tab })`。
  - 视频轨存在时，`ScreenSource` 直接从视频元素取帧。
  - 视频轨不可用（DRM/受保护页面）时，回退 `chrome.tabs.captureVisibleTab`。
- **窗口/屏幕模式**：`chrome.desktopCapture.chooseDesktopMedia(['screen', 'window'])` → offscreen `getUserMedia({ audio: desktop?, video: desktop })`。
  - 音频可选；没有音频轨时状态显示「窗口/屏幕音频不可用」。
- **摄像头**：独立 `getUserMedia({ video: true })`，与主画面并行推流；默认关闭。

### 4.2 视频声音采集

- 标签页或窗口/屏幕音频轨接入 `TabAudioCapture`：
  1. 本地回放给用户（因为 tabCapture 会接管原标签页音频）。
  2. 实时检测 RMS，判断视频是否真的在出声。
  3. 在本地做音量闪避：主 Agent 或主动评论发声时压低到约 16%，结束后平滑恢复。
  4. 把音频帧送入第二条 MOSS Live 连接（仅标签页/窗口声音）。
- 视频声音**绝不进入主会话的麦克风上行**。

### 4.3 视频监听会话

**连接参数**

| 参数 | 值 |
|---|---|
| model | `moss-live-1.0` |
| 输入音频 | 16kHz 单声道 PCM16，`0x00` tagged-v1 |
| 输出音频 | 不播放；`media.configure.playback = 'server'`，二进制丢弃 |
| 视频帧 | 不发送（主会话已有画面） |
| 画面参数 | 不适用 |
| 会话身份 | 当前角色人设 + 视频感知限定提示词 |

**视频监听提示词（按类型）**

通用前缀（始终包含）：

> 你是当前视频的感知层，只负责输出视频里正在发生的事实、台词、人物、剧情节点、梗、音乐/音效变化和摘要。不要对用户说话，不要扮演评论者，不要输出建议或提问。输出尽量短，按时间顺序。

按类型追加：

| 类型 | 摘要层级 | 追加要求 |
|---|---|---|
| 科普/知识 | 概念、术语、论点、数据、结论 | 标注关键定义和例子；不确定的专业内容标明「不确定」 |
| 短视频/段子 | 梗、笑点、上下文、关键台词 | 只抓笑点和反转，不复述整段 |
| 连续剧/电影 | 人物关系、剧情节点、伏笔、时间线 | 维护滚动剧情摘要；标注人物名和关系变化 |
| 音乐/MV | 歌曲、歌手、歌词情绪、画面氛围 | 识别歌曲/歌手时标注置信度；不确定不要编造 |
| 直播/体育 | 事件、比分、解说要点、时间节点 | 记录比分和关键事件；快节奏时只抓重点 |
| 通用 | 事实、对话、场景变化 | 保守摘要，不推测 |

**上下文注入格式**

```
[视频监听 @mm:ss | 类型: 连续剧/电影]
事实：……
关键台词：「……」
人物/剧情：……
摘要：……
```

通过 `session.thinking.append` 发给主会话，单条不超过 2000 字符。

**建连/断连**

- 视频声音持续约 300ms 超过阈值 → 建立第二条连接。
- 连续 30 秒静音 → 断开连接。
- 开关保持开启；下次检测到声音自动重建。
- 重建时把本地保存的视频类型、滚动摘要、最近关键台词作为初始上下文注入。

### 4.4 视频类型判断

- 自动判断依据：页面 URL、标题、视频时长、页面元数据、播放器标题、首段画面（复用主会话已发送的帧，不额外请求）。
- 判断结果在界面显示，用户可手动切换六类之一。
- 手动选择按视频 URL/标识保存，下一次打开同一视频优先使用用户选择。

## 5. 主会话与主动评论

### 5.1 主会话

- MOSS Live 连接 #1：麦克风 + 主画面 + 主语音播放。
- 角色：当前角色的人设、音色、说话风格。
- `session_id` 持久化；启动/重连时优先 resume。
- 重连：首次连接和断线都最多 3 次，指数退避；每次都记录并展示关闭码/原因。

### 5.2 主动评论

- 属于角色能力，由主会话发声。
- 角色编辑器新增「主动评论」三档：
  - **安静**：只在非常关键处评论；
  - **正常**（默认）：关键剧情、笑点、明显转折时评论；
  - **活泼**：更频繁地接话和评论。
- 触发：视频监听注入的上下文进入主会话后，主会话通过 `session.commentary.append` 发出可播报内容。
- 优先级：用户说话 > 主 Agent 回答 > 主动评论。
  - 用户开始说话：立即停止或压低主动评论；主 Agent 回答也让路给用户插话。
  - 主 Agent 正在回答：主动评论排队或丢弃，不叠加。
  - 视频原声在任何一方说话时都压低到约 16%。
- **待验证风险**：`session.commentary.append` 是否能让主连接主动播报，需真实 Key 冒烟测试；不通过时先回来讨论，不擅自改成监听连接发声。

### 5.3 角色系统

- 保留旧版角色、人设、音色。
- 默认角色「绫」。
- 角色编辑器新增「主动评论」档位。
- 主界面不强调角色管理；角色入口放在高级设置。

## 6. 消息模型与历史

### 6.1 消息结构

```js
{
  id: string,              // user-<turnKey> / assistant-<run_id>
  role: 'user' | 'assistant',
  text: string,
  final: boolean,
  runId?: string,
  turnId?: string,
  at: number,
  interrupted?: boolean,
  proactive?: boolean      // 主动评论标记（仍属于 assistant）
}
```

### 6.2 显示规则

| 输入 | 是否显示 | 显示位置 | 规则 |
|---|---|---|---|
| 用户麦克风转写 | 仅当最后麦克风活动在 2 秒内且 final | 「我」右侧气泡 | 每个 turn 一个独立 ID |
| 视频监听摘要 | 不显示 | — | 只走 `session.thinking.append` |
| 主 Agent 回复 | 显示 | 「你」左侧气泡 | 按 `run_id` 更新同一条 |
| 主动评论 | 显示 | 「你」左侧气泡，可加「主动」标记 | 作为 assistant 消息，绑定 run_id |

### 6.3 追加与覆盖

- 新消息只追加到列表尾部；同一 `id` 的流式更新只更新该条。
- 用户消息和 Agent 消息都不能被下一轮覆盖。
- 历史最多保留 500 条在内存；持久化写入 `chrome.storage.local`，跨浏览器重启保留。
- 切换陪看目标不重置消息列表。
- 关闭悬浮窗 / Side Panel 不重置消息列表。

## 8. 会话生命周期

### 8.1 开始

1. 检查 Relay `/health`：未启动或缺 Key 时提示并打开设置。
2. 检查权限：按 §3.2 申请缺失权限。
3. 窗口/屏幕模式先弹出选择器。
4. 创建/复用 offscreen 文档。
5. 启动麦克风、画面、视频声音采集。
6. 建立主会话连接 #1。
7. 视频声音开关开启时，等待 300ms 声音后建立视频监听连接 #2。
8. 状态变为「陪看中」。

### 8.2 结束

- 用户主动点击「结束陪看」：关闭两条连接、停止采集、关闭 offscreen。
- 用户主动关闭连接不算异常，不自动重连。

### 8.3 切换陪看目标

- 用户在另一个网页点击插件图标：
  1. 打开/聚焦悬浮窗或 Side Panel。
  2. background 通知 offscreen `tab-activated`。
  3. offscreen 获取新标签页 streamId，切换主会话画面和视频声音。
  4. 清空旧视频监听摘要/关键台词。
  5. 保留主会话连接、`session_id`、消息历史。
  6. 如果新标签页有视频声音，按 300ms 阈值重建视频监听连接。

### 8.4 断线

- 非用户主动关闭：最多自动重连 3 次，间隔 1s/2s/4s。
- 每次重连显示：
  - WebSocket 关闭码；
  - MOSS 返回的关闭原因；
  - Relay 错误（如有）。
- `session_id` 用于 resume；resume 失败则清掉旧 ID 新建一次。

## 9. Key 与本地 Relay

### 9.1 文件

| 文件 | 说明 | 是否提交 |
|---|---|---|
| `.env` | 实际 Key 和 Relay 配置 | 否，`.gitignore` 忽略 |
| `.env.example` | 模板，不含真实 Key | 是 |
| `server/relay.mjs` | 本地 Relay | 是 |
| `package.json` | `npm run relay` 脚本 | 是 |

### 9.2 `.env` 字段

```env
MOSS_API_KEY=
MOSS_RELAY_HOST=127.0.0.1
MOSS_RELAY_PORT=8787
MOSS_MODEL=moss-live-1.0
MOSS_UPSTREAM_URL=wss://api.mosi.cn/v1/realtime
```

### 9.3 Relay 行为

- `GET /health` 返回 `{ ok, hasKey, model, upstream }`，不返回 Key。
- WebSocket `/v1/realtime`：
  - 从 `.env` 读取 Key；
  - 给上游握手加 `Authorization: Bearer <Key>`；
  - 双向转发 JSON / 二进制帧；
  - 上游错误通过 `{ action: 'relay_error', data: { code, message } }` 发给插件；
  - 上游关闭通过 `{ action: 'relay_close', data: { code, reason, message } }` 发给插件。
- Relay 只监听 `127.0.0.1`，不对外网开放。

## 11. 风险与待验证

| 风险 | 影响 | 处理 |
|---|---|---|
| `session.commentary.append` 不一定触发主连接主动播报 | 主动评论可能不可用 | 真实 Key 冒烟验证；不通过先讨论备选，不擅自换方案 |
| 第二条 MOSS Live 连接产生额外费用和并发占用 | 成本/会话上限 | 默认待命、按声音建立、30 秒静音断开；界面说明 |
| 视频监听模型可能把视频声音当成“用户” | 摘要或行为偏差 | 提示词明确限定为视频感知层；不向主会话发送用户消息格式 |
| 视频类型自动判断可能不准 | 摘要层级不匹配 | 用户可手动切换并记住选择 |
| 主动评论可能打断观看 | 体验 | 三档频率、用户 > 主 Agent > 评论优先级、视频原声闪避 |
| DRM/受保护页面无法取视频轨 | 画面降级 | 回退截图；截图也失败时提示并继续音频 |
| Side Panel 权限弹窗不稳定 | 首次授权失败 | 完整扩展授权页兜底 |
| 切换标签页时 tabCapture 旧流未释放 | 新流获取失败 | 先停止旧流，确认释放后再获取新 streamId；失败时提示刷新页面 |
